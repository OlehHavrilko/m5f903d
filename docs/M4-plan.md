### 1.2. Что фактически есть по веткам B и C

В src/content/branches.ts все четыре ветки помечены ready: true, но в глубину
раскрыта только A:

| Ветка | Уровней в коде | Заявлено в scaleRange | Реально доступно |
|---|---|---|---|
| A engine | 9 | 0,6 м → 0,25 нм | всё |
| B at | 1 (at.unit) | 0,6 м → 1 мкм | только вход |
| C susp | 1 (susp.corner) | 0,5 м → 0,2 мм | только вход |
| D brake | 1 (brake.corner) | 0,3 м → 20 мкм | только вход (M5) |

Ветки B и C существуют как заглушки: src/branches/at/index.ts и
src/branches/susp/index.ts строят один агрегат из procgen/aggregates.ts.
Заявленные в интерфейсе диапазоны масштаба **шире, чем реальная глубина** — это
расхождение с принципом честности проекта и должно закрыться в M4.

### 1.3. Найденные дефекты и долги

1. **Неполная глубина B/C** — главный пункт M4 (см. §3).
2. **Нет CI.** В README.md сказано, что GitHub Actions недоступен из-за scopes
   токена. Проверено сейчас: у токена есть scope workflow, ограничение снято —
   CI пора включить (отдельный маленький PR, §3 шаг M4.1).
3. **Нет .gitattributes.** На Windows core.autocrlf=true, локальный
   prettier --check ругается на CRLF почти во всех файлах, при этом в CI на Linux
   проверка проходит. Плавающая проверка — плохо; лечится .gitattributes.
4. **.npm-cache/** (локальный кэш npm, вынужденная мера из-за песочницы) не в
   .gitignore.
5. **Только unit-слой тестов.** Визуальные baseline, DOM-аудит и Playwright-e2e из
   M0 §9 не заведены — это M6.
6. **guide/** описывает у B/C/D только входные уровни и прямо пишет, что полные
   гайды будут в M5. После M4 гайд по B и C нужно достроить.

## 2. Цель M4 и критерии приёмки

**Цель:** ветки B и C проходятся от хаба до последнего уровня так же, как ветка A:
непрерывный зум, данные с источниками, честные пометки упрощений, тесты без GPU.

Критерии приёмки:

- Ветка B: 7 уровней, ветка C: 6 уровней; порядок строго по убыванию масштаба.
- Каждый уровень: title/subject/geometry/animation на en/ru/uk, непустой
  simplified, непустые sources, числа с source либо unverified: true.
- Для каждого уровня есть билдер с конечной геометрией, переживающий полный цикл
  update(); тест-паттерн — как tests/unit/engine-branch.test.ts.
- Новая физика вынесена в чистые модули src/procgen/transmission.ts и
  src/procgen/suspension.ts и покрыта тестами.
- guide/ дополнен разделами по всем новым уровням B и C.
- BRANCHES[].scaleRange совпадает с реальным диапазоном уровней.
- npm run check зелёный (в CI).

## 5. Риски

1. **Раздувание бандла.** Данные уровней остаются в основном чанке, геометрия — в
   динамическом чанке ветки. Бюджет M0 §6.1 (ветка ≤ 120 КБ gzip) проверяется в CI.
2. **Детерминизм.** Никаких Math.random()/Date.now() в кадре: джиттер и
   распределения берутся из существующего seeded-модуля.
3. **Честность чисел.** Для АКПП и подвески публичных данных меньше, чем для ДВС:
   риск подставить «красивое» число. Правило — либо источник, либо unverified.
4. **Рассинхрон данных и геометрии.** BRANCHES[].scaleRange и ready правятся
   только вместе с фактическим набором уровней; тест ветки проверяет соответствие.
