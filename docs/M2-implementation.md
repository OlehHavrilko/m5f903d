## 2. Хаб и ветки

Хаб (`chassis-hub`) — обычный уровень: непрерывный зум из `body` приводит к нему. Внутри
показана ходовая часть под полупрозрачным кузовом. Каждый агрегат помечен `userData.entry`:

```
engine → engine.unit    at → at.unit    susp → susp.corner    brake → brake.corner
```

Клик по агрегату или карточке в панели веток вызывает `activateLevel(id)`. Уровень-цель
принадлежит ветке; `branch-loader` динамически подтягивает чанк ветки, кладёт её билдеры в
общий `Map` и только потом запускает seam. Поэтому вход в ветку — это тот же непрерывный
переход, что и внутри спины, а не монтажная склейка.

`BRANCHES` — единственный источник правды для панели: заголовок, описание, диапазон масштаба,
цвет-акцент, уровень входа и флаг `ready`. Когда ветка не готова, карточка выключена и помечена
«следующие этапы»; сейчас готовы все четыре.

## 3. Сквозной маршрут M2

```
studio ⇄ car ⇄ body ⇄ chassis-hub
                         ├─ engine.unit   (динамический чанк)
                         ├─ at.unit       (динамический чанк)
                         ├─ susp.corner   (динамический чанк)
                         └─ brake.corner  (динамический чанк)
```

Между спиной и первой веткой `neighbour()` работает сквозным образом:
`chassis-hub → engine.unit → at.unit → …`, поэтому `→`/`‹`/`›` идут по всему дереву, а `Home`
возвращает на `studio`.

## 4. Исправление масштабов против M0

В M0 шкала ветки B была задана как 0,15 м для `at.unit`. Реальный корпус 8HP — порядка
0,6 м в длину (ZF 8HP catalogue), поэтому в M2 у `at.unit` стоит `scale.unitMeters = 0.62`
и кадр 0,98 м, иначе шкала врала бы на порядок. Остальные входы сохранены.

## 5. Бюджеты бандла

| Чанк | gzip |
|---|---|
| `main` (ядро + спина + агрегаты) | ≈36,1 КБ |
| `three` | ≈122,3 КБ |
| **Итого начальный JS** | **≈158,4 КБ** (лимит 320 КБ) |
| каждя ветка (`index-*.js`) | 0,31–0,35 КБ (лимит 120 КБ) |

Агрегаты (двигатель, коробка, угол подвески, тормоз) общие для хаба и ветвей, поэтому лежат в
основном чанке; ветки несут только входные уровни. Рост `main` против M1 (+14,7 КБ gzip) — это
`body`, `chassis`, `aggregates` и панель веток.

## 6. Тесты без GPU (`npm test`)

60 тестов; к M1 добавлены:

- `body` — каркас с панелями, разлёт и детерминированный возврат панелей на место;
- `chassis` — ходовая собирается, геометрия конечна, есть два пути потока, `flow` включается;
- `branches` — каждая готовая ветка грузится и строит конечную геометрию, неизвестная ветка
  возвращает `{}`;
- `levels` — спина и ветки лежат непрерывными блоками, ровно один `hub`, режимы валидируются.

## 7. Известные ограничения (и когда закрываются)

- **Ветки — только входные уровни.** `engine.unit`, `at.unit`, `susp.corner`, `brake.corner`
  собраны схематично. Глубина (цилиндр, сгорание, планетарные ряды, амортизатор, фрикционная
  пара, рейка, микро-масштабы) — M3–M5.
- **Визуальные baseline и e2e** по-прежнему недоступны в этом окружении (нет системных
  библиотек Chromium); интерфейсы `Stage`/`LevelManager`/`LevelContent` детерминированы.
- **A11y-аудит вёрстки** (8 вьюпортов) не автоматизирован; вёрстка ручная, проверена на 320 px.
- Интерьер и электроника вне области разбора.

## 8. Как это посмотреть

```bash
npm install
npm run dev
```

- холодный визит → интро → `studio`; далее `→`, чтобы дойти до `chassis-hub`;
- на хабе — панель веток: тап по карточке или по агрегату в сцене;
- `#l=engine.unit` — прямой вход в ветку (грузятся только её чанки);
- `#l=chassis-hub&mode=flow` — потоки момента;
- `#l=body&mode=explode` — разлёт панелей;
- кнопки фона **белый / серый / чёрный** и «пол» в верхнем баре.
